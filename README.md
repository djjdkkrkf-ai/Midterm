# Contact CRUD (React + React Router + API)

เว็บเข้าสู่ระบบและจัดการ Contact (สร้าง / อ่าน / แก้ไข / ลบ) โดยเชื่อมกับ API จริง `https://nest-js-basic-api.onrender.com`

## วิธีรัน

```bash
pnpm install
pnpm dev
```

เปิด http://localhost:5173 แล้วเข้าสู่ระบบด้วย `student1@mail.com` ถึง `student60@mail.com` รหัสผ่าน `1234567891011`

> ต้องใช้พอร์ต 5173 เท่านั้น เพราะ API อนุญาต CORS ให้พอร์ตนี้ (ตั้ง `strictPort` ไว้ใน `vite.config.js`)

## โครงสร้างไฟล์

```
src/
  main.jsx              จุดเริ่มต้น ครอบแอปด้วย BrowserRouter
  App.jsx               กำหนด Routes + เก็บสถานะล็อกอิน (token, email)
  api.js                ฟังก์ชันกลางสำหรับเรียก API (แนบ Bearer token)
  style.css             สไตล์ทั้งหมด (รวมธีมมืด)
  pages/Login.jsx       หน้าเข้าสู่ระบบ
  pages/Contacts.jsx    หน้ารายการ Contact (Read + Delete)
  pages/ContactForm.jsx หน้าสร้าง / แก้ไข Contact (Create + Update)
  components/Topbar.jsx แถบด้านบน: สลับธีม / อีเมล / ออกจากระบบ
  components/Icon.jsx   ไอคอน SVG
  components/ConfirmDelete.jsx กล่องยืนยันการลบ
```

| URL | หน้า |
|---|---|
| `/login` | เข้าสู่ระบบ |
| `/contacts` | รายการ Contact |
| `/contacts/new` | สร้าง Contact |
| `/contacts/:id/edit` | แก้ไข Contact |

## ตอบคำถาม

### 1. CRUD Object

Object คือข้อมูลแบบ `key: value` จัดการได้ 4 แบบ

```js
const contact = { firstName: 'Somchai', company: 'Acme' };   // Create
contact.firstName;                                            // Read   → 'Somchai'
const updated = { ...contact, company: 'Bangkok Studio' };    // Update (สร้าง object ใหม่ ไม่แก้ของเดิม)
const { company, ...withoutCompany } = contact;               // Delete (ตัด key ออก)
```

ในโปรเจกต์ใช้ตอนอัปเดตฟอร์ม: `setForm({ ...form, [k]: e.target.value })` คัดลอก object เดิมแล้วแทนเฉพาะช่องที่พิมพ์

### 2. CRUD Array

```js
let list = [{ id: 1, name: 'A' }];
list = [...list, { id: 2, name: 'B' }];                       // Create (เพิ่มท้าย)
list[0]; list.find(...)                                       // Read
list = list.map(x => x.id === 2 ? { ...x, name: 'B2' } : x);  // Update
list = list.filter(x => x.id !== 1);                          // Delete
```

ใน React จะไม่ใช้ `push` / `splice` กับ state เพราะเป็นการแก้ของเดิม React จะไม่รู้ว่าข้อมูลเปลี่ยน ต้องสร้าง array ใหม่เสมอ

### 3. Array – หาข้อมูลด้วย `find`

`find` คืนค่า **ตัวแรก** ที่เงื่อนไขเป็นจริง ถ้าไม่เจอคืน `undefined`

```js
const c = contacts.find(c => c.id === id);
if (!c) console.log('ไม่พบข้อมูล');
```

### 4. Array – Update ด้วย `map`

`map` สร้าง array ใหม่ที่มีจำนวนเท่าเดิม ตัวที่ตรงเงื่อนไขแทนด้วยค่าใหม่ ตัวอื่นคืนค่าเดิม

```js
setContacts(contacts.map(c => c.id === id ? { ...c, ...changes } : c));
```

ในโปรเจกต์ `map` ยังใช้ในการแสดงผลรายการ: `items.map(c => <tr key={c.id}>...</tr>)`

### 5. Array – Delete ด้วย `filter`

`filter` สร้าง array ใหม่ที่เหลือเฉพาะตัวที่เงื่อนไขเป็นจริง

```js
setContacts(contacts.filter(c => c.id !== id));
```

### 6. React Component คืออะไร?

ฟังก์ชันที่คืนค่าเป็น UI (JSX) นำมาใช้ซ้ำและประกอบกันเป็นหน้าเว็บได้ เช่น `<Topbar />` ถูกใช้ร่วมกันทุกหน้าหลังล็อกอิน และ `<Icon name="edit" />` ใช้ซ้ำหลายที่ แต่ละ component มี state และหน้าที่ของตัวเอง ทำให้โค้ดแยกส่วนอ่านง่าย

### 7. State กับ Props ต่างกันอย่างไร?

| | State | Props |
|---|---|---|
| คืออะไร | ข้อมูลที่ component **เป็นเจ้าของ** และเปลี่ยนได้ | ข้อมูลที่ **ส่งมาจาก component แม่** |
| เปลี่ยนค่า | ผ่าน `setState` แล้วหน้าจอ render ใหม่ | ลูกแก้เองไม่ได้ (read-only) |
| ตัวอย่างในโปรเจกต์ | `form`, `error`, `loading` ใน `Login.jsx` | `token`, `onLogout` ที่ `App` ส่งให้ `<Contacts token={token} onLogout={logout} />` |

ถ้าลูกอยากเปลี่ยนข้อมูลของแม่ แม่ต้องส่งฟังก์ชันมาเป็น props เช่น `onLogin` ใน `Login`

### 8. useEffect คืออะไร?

Hook สำหรับทำงานที่เป็น "ผลข้างเคียง" หลัง render เช่น ดึงข้อมูลจาก API, ตั้งค่า `localStorage`, แก้ DOM ทำงานตาม dependency array

- `useEffect(() => { load(); }, [])` ใน `Contacts.jsx` → ทำครั้งเดียวตอนเปิดหน้า เพื่อดึงรายการ
- `useEffect(() => {...}, [id])` ใน `ContactForm.jsx` → ทำใหม่เมื่อ `id` ใน URL เปลี่ยน เพื่อโหลดข้อมูลมาแก้ไข
- `useEffect(() => {...}, [theme])` ใน `Topbar.jsx` → ทุกครั้งที่สลับธีม จะตั้ง `data-theme` และบันทึกลง `localStorage`

### 9. Global state คืออะไร?

state ที่หลายหน้า / หลาย component ต้องใช้ร่วมกัน เช่น ข้อมูลผู้ใช้ที่ล็อกอิน ทำได้หลายวิธี เช่น Context API, Redux, Zustand

ในโปรเจกต์นี้ใช้วิธีง่ายที่สุดคือ **ยก state ขึ้นไปไว้ที่ `App`** (`token`, `email`) แล้วส่งลงไปเป็น props ให้หน้าที่ต้องใช้ และเก็บสำเนาใน `localStorage` เพื่อให้อยู่รอดหลังรีเฟรช ถ้าแอปใหญ่ขึ้นและต้องส่ง props หลายชั้น ควรเปลี่ยนไปใช้ Context

### 10. การทำงานของหน้า login

1. ผู้ใช้พิมพ์ → `onChange` เรียก `set('email')` / `set('password')` เก็บค่าใน state `form = { email, password }` (เป็น controlled input: ค่าในช่องมาจาก state)
2. กดปุ่ม "เข้าสู่ระบบ" → `submit()` เรียก `e.preventDefault()` กันหน้ารีโหลด
3. ตรวจข้อมูล (ดูข้อ 17) ถ้าผิดแสดงตัวแดงแล้วหยุด
4. ตั้ง `loading = true` ปุ่มเปลี่ยนเป็น "กำลังเข้าสู่ระบบ..." และกดไม่ได้
5. ส่งข้อมูลเป็น **JSON** ด้วย `POST /auth/login`
   ```json
   { "email": "student1@mail.com", "password": "1234567891011" }
   ```
6. API ตอบ `{ success, data: { accessToken, user: { email, ... } } }` → `api.js` คืนค่า `data`
7. เรียก `onLogin(token, email)` บันทึกลง state และ `localStorage` แล้ว `navigate('/contacts')` → หน้าจอเปลี่ยนเป็นหน้ารายการ Contact พร้อมแถบด้านบนที่แสดงอีเมล

### 11. เก็บสถานะ "ล็อกอินแล้ว" ไว้ที่ไหน

เก็บ **2 ที่**

- **state ใน `App`** (`token`, `email`) → ทำให้ React render หน้าใหม่ทันทีเมื่อล็อกอิน / ออกจากระบบ
- **`localStorage`** (`token`, `email`) → เพราะ state หายเมื่อรีเฟรช จึงต้องมีที่เก็บถาวรในเบราว์เซอร์ ตอนเปิดแอป `useState(() => localStorage.getItem('token'))` จะอ่านกลับมา

**รีเฟรชแล้วยังล็อกอินอยู่** ไม่เลือก cookie เพราะ API นี้รับ token ผ่าน header `Authorization: Bearer ...` ไม่ได้อ่านจาก cookie และ localStorage ใช้ง่ายกว่า (ข้อเสีย: JavaScript อ่านได้ จึงต้องระวัง XSS)

ถ้า token หมดอายุ API ตอบ 401 → หน้ารายการเรียก `onLogout()` ลบ token แล้วกลับหน้า login

### 12. Read (รายการ)

1. เปิด `/contacts` → `useEffect` เรียก `load()`
2. `GET /contacts?limit=100` พร้อม header `Authorization: Bearer <token>`
3. API ตอบ `{ data: { items: [...] } }` → `setItems(d.items)`
4. `items.map(...)` สร้างแถวในตาราง

ใช้ state 2 ตัว: `items` (ข้อมูล, เริ่มต้น `null` = ยังไม่ได้โหลด) และ `loadError` (ข้อความผิดพลาด)

| สถานะ | เงื่อนไข | หน้าจอ |
|---|---|---|
| กำลังโหลด | `items === null` และไม่มี error | แสดง "กำลังโหลด..." |
| ว่าง | `items.length === 0` | แสดง "ยังไม่มี Contact" |
| มีข้อมูล | `items.length > 0` | แสดงตาราง |
| ผิดพลาด 401 (token หมดอายุ) | `e.status === 401` | ออกจากระบบอัตโนมัติ กลับหน้า login |
| ผิดพลาดอื่น ๆ (เน็ตหลุด, server error) | `loadError` มีค่า | แสดง "โหลดรายการไม่สำเร็จ (สาเหตุ)" สีแดง พร้อมปุ่ม **ลองอีกครั้ง** |

```js
api('/contacts?limit=100', { token })
  .then((d) => setItems(d.items))
  .catch((e) => (e.status === 401 ? onLogout() : setLoadError(e.message)));
```

กด "ลองอีกครั้ง" → ล้าง error, ตั้ง `items` กลับเป็น `null` (กลับไปสถานะกำลังโหลด) แล้วเรียก `load()` ใหม่

### 13. Read (รายตัว)

ใช้ **URL param**: กดปุ่มแก้ไข → `navigate('/contacts/<id>/edit')` → ใน `ContactForm` อ่าน `id` ด้วย `useParams()` → `GET /contacts/:id` แล้วนำข้อมูลใส่ฟอร์ม

ข้อดีของการใช้ URL คือรีเฟรชหรือแชร์ลิงก์แล้วยังเปิดรายการเดิมได้ (ถ้าเก็บไว้ใน state จะหายตอนรีเฟรช)

**ถ้าไม่พบ** ดูจาก status ที่ API ตอบ

| API ตอบ | ความหมาย | หน้าจอ |
|---|---|---|
| 404 `NOT_FOUND` | ไม่มี id นี้ หรือถูกลบไปแล้ว | ตั้ง `notFound = true` → แสดงกล่อง **"ไม่พบข้อมูล Contact"** พร้อมปุ่ม "กลับไปรายการ" แทนฟอร์ม |
| 400 `VALIDATION_ERROR` | id ผิดรูปแบบ (ไม่ใช่ UUID) เช่น `/contacts/abc/edit` | เหมือน 404 |
| error อื่น ๆ | เน็ตหลุด / server ล่ม | แสดงฟอร์มพร้อมข้อความ "โหลดข้อมูลไม่สำเร็จ (สาเหตุ)" |

```js
.catch((e) => ([400, 404].includes(e.status) ? setNotFound(true) : setError(`โหลดข้อมูลไม่สำเร็จ (${e.message})`)));
```

ไม่แสดงฟอร์มเปล่าเมื่อไม่พบ เพราะผู้ใช้อาจเข้าใจผิดแล้วกดบันทึก ซึ่งจะ PATCH ไปยัง id ที่ไม่มีอยู่

### 14. Create

1. กด "+ สร้าง Contact" → `<Link to="/contacts/new">` เปิดฟอร์ม (`id` ไม่มี = โหมดสร้าง)
2. ฟอร์มเริ่มจาก `empty = { firstName: '', lastName: '', email: '', phone: '', address: '', company: '' }`
3. พิมพ์ → `setForm({ ...form, [k]: value })`
4. กด "สร้าง Contact" → ตรวจ `firstName` ต้องไม่ว่าง
5. แปลงข้อมูล: ตัดช่องว่างหัวท้าย และช่องที่ว่างส่งเป็น `null` (API ไม่รับสตริงว่าง)
6. ส่ง `POST /contacts` เป็น JSON
   ```json
   { "firstName": "Somchai", "lastName": "Jaidee", "email": null, "phone": null, "address": null, "company": "Acme" }
   ```
7. สำเร็จ → `navigate('/contacts')` หน้ารายการโหลดใหม่และเห็นรายการที่เพิ่งสร้าง

### 15. Update

- **ข้อมูลเดิมเข้าฟอร์ม:** `useEffect` โหลด `GET /contacts/:id` แล้วแปลงค่า `null` เป็น `''` (เพราะ input ต้องการ string) ก่อน `setForm(...)`
- **ฟอร์มใช้ร่วมกัน** (`ContactForm.jsx` ไฟล์เดียว) เพราะช่องและกฎตรวจเหมือนกันทุกอย่าง ต่างกันแค่หัวข้อ, ปุ่ม และ method การส่ง ดูจากว่ามี `id` หรือไม่
  ```js
  api(id ? `/contacts/${id}` : '/contacts', { method: id ? 'PATCH' : 'POST', ... })
  ```
- **หลังบันทึก:** ส่ง `PATCH /contacts/:id` → `navigate('/contacts')` → หน้ารายการดึงข้อมูลใหม่จาก API จึงเห็นค่าที่แก้แล้ว

### 16. Delete

1. กดปุ่มถังขยะ → `setToDelete(c)` เก็บ Contact ที่จะลบไว้ใน state → กล่อง `<ConfirmDelete />` เปิดขึ้น แสดงชื่อและข้อความ "การลบไม่สามารถย้อนกลับได้"
2. **ยกเลิกได้ 3 ทาง:** กดปุ่ม "ยกเลิก", กดพื้นหลังมืดนอกกล่อง หรือกด `Esc` → `setToDelete(null)` กล่องปิด ไม่มีอะไรถูกลบ
3. กด "ลบ" → `deleting = true` ปุ่มเปลี่ยนเป็น "กำลังลบ..." และกดซ้ำ / ปิดกล่องไม่ได้ระหว่างรอ
4. ส่ง `DELETE /contacts/:id` (API ตอบ 204 ไม่มีเนื้อหา)
5. สำเร็จ → ปิดกล่อง แล้วเรียก `load()` **ดึงรายการใหม่จาก API** / ล้มเหลว → กล่องยังเปิดอยู่ แสดง "ลบไม่สำเร็จ (สาเหตุ)" ให้กดลองใหม่หรือยกเลิกได้

ใช้กล่องที่ทำเองแทน `window.confirm()` ของเบราว์เซอร์ เพราะจัดหน้าตาให้เข้ากับเว็บได้ (รวมธีมมืด) แสดงชื่อรายการชัดเจน และแสดงสถานะกำลังลบ / error ในกล่องเดียวกันได้

เลือกดึงใหม่แทนการ `filter` ออกจาก state เพราะข้อมูลบนจอตรงกับฐานข้อมูลจริงเสมอ (เช่น ถ้ามีการเปลี่ยนจากที่อื่น) แลกกับการเรียก API เพิ่มหนึ่งครั้ง ถ้าต้องการให้เร็วขึ้นใช้ `setItems(items.filter(x => x.id !== c.id))` แทนได้

### 17. Validate ฝั่งหน้าจอ

| ฟอร์ม | ตรวจอะไร |
|---|---|
| Login | อีเมลต้องตรงรูปแบบ `/^\S+@\S+\.\S+$/`, รหัสผ่านต้องไม่ว่าง |
| Contact | `firstName` ต้องไม่ว่าง (หลังตัดช่องว่าง) |

**ตรวจเมื่อไร:** ตอน **กดบันทึก / กดเข้าสู่ระบบ** เท่านั้น ไม่ได้ตรวจตอนพิมพ์หรือตอนออกจากช่อง เพื่อไม่ให้ขึ้นตัวแดงก่อนผู้ใช้กรอกเสร็จ แต่หน้า login **ล้างตัวแดงทันทีเมื่อเริ่มพิมพ์** ในช่องนั้น

ใส่ `noValidate` ที่ `<form>` เพื่อปิด popup ตรวจของเบราว์เซอร์ ให้ใช้ข้อความภาษาไทยของเราแทน

นอกจากนี้ API ก็ตรวจซ้ำฝั่ง server ด้วย (เช่น สตริงว่าง) ถ้าไม่ผ่านจะแสดงข้อความจาก API (ดูข้อ 19)

### 18. ข้อความ error และปุ่มบันทึก

- **Login:** error แสดง **ใต้ช่องที่ผิด** พร้อมกรอบแดง (`className="invalid"`) แยกรายช่อง ส่วน error จาก API แสดงเหนือปุ่ม
- **Contact:** error แสดง **เหนือปุ่มบันทึก** เป็นข้อความสีแดง
- **ปุ่มบันทึก** ยังกดได้เมื่อข้อมูลไม่ถูกต้อง แต่กดแล้วจะไม่ส่งข้อมูล แสดง error แทน (บอกผู้ใช้ได้ชัดกว่าการปิดปุ่มเฉย ๆ)
- **ฟอร์มสร้างกับแก้ไขใช้กฎชุดเดียวกัน** เพราะเป็น component เดียวกัน

### 19. เมื่อการส่งข้อมูลล้มเหลว

- `api.js` โยน error พร้อมข้อความจาก API (`json.error.message`) และ status code
- **หน้าจอ:** แสดง `บันทึกไม่สำเร็จ (ข้อความ)` / `เข้าสู่ระบบไม่สำเร็จ (ข้อความ)` ถ้าเครือข่ายหลุดจะเห็น `(Failed to fetch)` ถ้ารหัสผิด (401) แสดง "อีเมลหรือรหัสผ่านไม่ถูกต้อง"
- **กันกดซ้ำ:** ระหว่างรอ `saving` / `loading = true` → ปุ่ม `disabled` กดไม่ได้ (หน้า login ข้อความปุ่มเปลี่ยนเป็น "กำลังเข้าสู่ระบบ...") พอผิดพลาดจะเปิดปุ่มกลับให้ลองใหม่
- **ข้อมูลที่กรอกยังอยู่ครบ** เพราะเก็บใน state `form` และไม่ได้ล้างเมื่อผิดพลาด ล้าง/เปลี่ยนหน้าเฉพาะเมื่อสำเร็จ

### 20. ปรับแก้ UI จากเว็บเดิม

| ส่วน | เว็บเดิม | เว็บนี้ |
|---|---|---|
| หน้า login | การ์ดเดียว ปุ่มสีน้ำเงิน | แบ่งสองฝั่ง ซ้ายไล่สีชมพู→ส้ม พร้อมกล่องบัญชีประจำห้องเรียน ขวาเป็นฟอร์ม |
| ช่องกรอก / ปุ่ม | มุมโค้งเล็ก | ทรงแคปซูล ปุ่มไล่สีพร้อมเงา |
| โทนสี | น้ำเงิน / เทา | ชมพูกุหลาบ + ส้ม พื้นหลังไล่สีอ่อน |
| แถบด้านบน | มีชื่อเว็บ + breadcrumb | ตัดออก เหลือปุ่มธีม / อีเมล / ออกจากระบบ และเพิ่มเส้นสีรุ้งด้านบน |
